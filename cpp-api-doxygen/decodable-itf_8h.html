Detailed Description

The scoring interface between acoustic models and the decoders.

This file is copied/modified from src/itf/decodable-itf.h. Every decoder in this library consumes acoustic scores exclusively through DecodableInterface; the library therefore contains no acoustic-model code at all. GMMs, neural nets, CTC posteriors and Python prototypes can all drive the same decoders.

The interface answers exactly one question:

\[ \mathrm{LogLikelihood}(t, i) = \log p\bigl(\text{label } i \,\big|\, \text{frame } t\bigr), \]

where labels are one-based transition-ids (openfst convention: 0 is epsilon). Higher is better; the decoder adds graph costs separately.

class MyDecodable : public kaldi_decoder::DecodableInterface {
public:
float LogLikelihood(int32_t frame, int32_t index) override {
return scores_(frame, index - 1); // labels are one-based
}
int32_t NumFramesReady() const override { return scores_.rows(); }
bool IsLastFrame(int32_t frame) const override {
return frame == NumFramesReady() - 1;
}
int32_t NumIndices() const override { return scores_.cols(); }
};

Common ownership rules:

  • Decoders borrow the decodable and the graph; they never free them
  • Matrix-backed decodables copy (and own) their input matrix unless the borrowing constructor is used
  • Lattices returned by GetBestPath()/GetRawLattice() are owned by the caller

General usage pattern:

  1. Provide scores through a DecodableInterface implementation
  2. Construct a decoder with the decoding graph
  3. Decode (one-shot Decode() or InitDecoding()/AdvanceDecoding())
  4. Query ReachedFinal()/GetBestPath()/GetRawLattice()
  5. Release the objects you own (graphs/decodables in the caller)

Runnable examples live in kaldi-decoder/python/tests/ and in the docs (usage/decoding.rst, usage/alignment.rst, usage/streaming.rst).
